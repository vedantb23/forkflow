# Frontend UI Integration Plan

The new UI generated by Stitch looks stunning! Since the generated output consists of raw, static HTML/CSS strings, our goal is to meticulously port these designs into our Next.js React application. 

We will break the static HTML apart into reusable React components, configure the rich Tailwind color palette, set up the global theme provider (Light/Dark mode), and wire up the UI to be ready for the backend APIs and Socket.io.

## User Review Required

> [!IMPORTANT]
> The generated UI uses Google Material Symbols. I will include the font link in the root `layout.tsx` so the icons render correctly.
> The UI includes custom CSS keyframes (e.g. `fade-up`, `pulse-ring`). I will port these into the global CSS or Tailwind config.
> I will install `next-themes` for the Dark/Light mode toggle, and `framer-motion` for smooth React animations.

## Proposed Changes

### 1. Configuration & Layout Layer
#### [MODIFY] `frontend/package.json`
- Install `next-themes` (for dark mode) and `framer-motion`.

#### [MODIFY] `frontend/src/app/globals.css`
- Port the extensive color palette (`primary`, `surface-dim`, `on-tertiary-container`, etc.) from the HTML `<script id="tailwind-config">` into the Tailwind v4 `@theme` directive.
- Add the custom keyframes (`fade-up`, `pulse-ring`, `slideUpCart`, `pulseItem`) and `.hide-scroll` utility classes.

#### [MODIFY] `frontend/src/app/layout.tsx`
- Add Google Fonts links for `Inter` and `Material Symbols Outlined`.
- Wrap the app in `<ThemeProvider attribute="class" defaultTheme="system" enableSystem>`.
- Build the `TopNavBar` and `Footer` components directly into the layout (or as client components if they need state) so they persist across pages.

### 2. Page Conversions (HTML to React Components)
We will convert each HTML page into its respective Next.js Route.

#### [MODIFY] `frontend/src/app/page.tsx` (Home Page)
- Convert the hero banner, category chips, and "Featured Collections" grid into a dynamic React component.
- Convert raw `<img>` tags to `next/image` or standard React `<img />`.

#### [MODIFY] `frontend/src/app/register/page.tsx` (Auth & Role Picker)
- Convert the split-screen login/register UI.
- Implement React state for the **Role Picker** (`CUSTOMER`, `RESTAURANT_OWNER`, `DELIVERY`) using `useState` instead of raw DOM manipulation.

#### [MODIFY] `frontend/src/app/restaurants/[id]/page.tsx` (Restaurant Menu & Cart)
- Convert the menu categories and item grids.
- Implement the Floating Cart bar using a local state (or Zustand) so it reacts to "Add to Cart" button clicks.

#### [MODIFY] `frontend/src/app/orders/[id]/page.tsx` (Live Order Tracking)
- Convert the ETA hero card, live timeline (Confirmed → Preparing → Out for Delivery → Delivered), and the driver info panel.
- Ensure the map background and the absolutely-positioned delivery bike marker are structured cleanly, ready to accept real-time GPS coordinates via Socket.io.

#### [MODIFY] `frontend/src/app/dashboard/delivery/page.tsx` (Delivery Portal)
- Convert the SideNavBar layout.
- Implement the "Active Trip" card (with the pickup/delivery stops) and the "Available Deliveries" list.

#### [MODIFY] `frontend/src/app/dashboard/restaurant/page.tsx` (Restaurant Portal)
- Convert the SideNavBar layout.
- Implement the "Go Live" toggle switch using React state.
- Create the Kanban-style columns (Incoming, Preparing, Ready) for the live orders feed.

## Verification Plan

### Automated Tests
- Run `npm run dev` in the frontend to ensure Next.js compiles without errors.
- Check that Tailwind v4 recognizes the custom colors (e.g., `bg-surface-dim`, `text-primary`).

### Manual Verification
- We will visually verify the Home Page, Register, Menu, Tracking, Delivery Dashboard, and Restaurant Dashboard by navigating to their respective routes.
- Ensure the Dark Mode toggle (using `next-themes`) correctly flips the `dark` class on the `<html>` element and the UI responds appropriately.
